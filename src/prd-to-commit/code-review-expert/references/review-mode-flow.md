# 代码审查

本技能用于代码审查，生成审查报告。支持三种模式（均只检查增量代码）：

1. **指定分支模式**：切换到生产分支，合并指定分支，审查增量代码
2. **指定路径模式**：检查指定路径下相对于基准分支的增量代码
3. **当前变更模式**：直接检查当前还未提交的增量代码

## 参数

- branch：可选参数，指定要合并的远程分支（支持多个，用逗号分隔）。如果未提供，则评审当前分支的变更。
- branches：可选参数，指定要合并的远程分支数组（与branch二选一）。
- path：可选参数，指定要检查的路径或文件。可选指定基准分支，格式为 `路径@基准分支`，如 `src/utils@master`。

## 步骤一：检查当前分支

首先检查当前所在分支：

```bash
git branch --show-current
```

## 步骤二：确定审查模式

根据用户输入判断审查模式：

1. **如果用户指定了分支**（参数 branch 或 branches）：
   - 切换到生产分支，然后合并指定分支进行审查
   - 执行「步骤三」切换生产分支

2. **如果用户指定了路径**（参数 path）：
   - 直接检查当前分支下该路径的所有代码
   - 无需切换分支，直接执行「步骤四」进行代码审查

3. **如果用户未指定任何参数**：
   - 直接检查当前还未提交的变更代码
   - 无需切换分支，直接执行「步骤四」进行代码审查

## 步骤三：切换生产分支（仅当用户指定分支时执行）

如果当前分支不是生产分支，执行切换：

1. **如果用户指定了分支**（参数 branch 或 branches）：

   ```bash
   git checkout <用户指定的分支>
   ```

2. **如果用户未指定分支**（使用默认生产分支）：
   - 默认生产分支：`master`

   执行切换：

   ```bash
   git checkout master
   ```

## 步骤三（续）：确认切换成功并拉取最新代码并判断项目类型

切换后执行以下命令确认并拉取最新代码：

```bash
git branch --show-current
git pull origin master
```

确保输出为目标分支名称，并保持代码与远程同步。

### 3.1 判断项目类型

根据项目目录结构和配置文件判断前端框架类型：

**Vue项目特征**：

- 存在 `vue.config.js` 或 `vite.config.js`（含 vue 配置）
- 存在 `src/views` 或 `src/components` 目录
- 存在 `.vue` 文件
- `package.json` 中包含 `vue` 依赖

**React项目特征**：

- 存在 `vite.config.js`（含 react 配置）或 `webpack.config.js`
- 存在 `src/pages` 或 `src/components` 目录
- 存在 `.jsx` 或 `.tsx` 文件
- `package.json` 中包含 `react` 依赖

```bash
ls -la
cat package.json | grep -E '"vue"|"react"'
```

根据判断结果确定项目类型，后续审查时应用对应的框架规范。

## 步骤四：代码审查

### 4.1 处理审查目标

**用户指定分支时的处理方式**：

1. **如果用户指定了单个分支**（参数 branch）：
   将其转换为数组：`[branch]`

2. **如果用户指定了多个分支**（参数 branches）：
   直接使用数组

3. **如果用户指定了逗号分隔的分支字符串**（如 "branch1,branch2,branch3"）：
   分割为数组

**用户指定路径时的处理方式**：

- 直接在当前分支下检查该路径的增量代码
- 默认与 master 分支比较变更
- 可通过 `@基准分支` 指定比较分支
- 不切换分支，不合并代码

1. **解析路径参数**：
   - 格式：`路径` 或 `路径@基准分支`
   - 如 `src/utils` 或 `src/utils@develop`

2. **获取增量文件**：
   - 获取该路径下与基准分支的差异文件
   - 只检查变更的文件，不检查未变更的文件

```bash
# 解析路径参数
# path = "src/utils@master"
# base = "master"（默认）

# 用户指定路径时
# 判断是目录还是文件，并提取基准分支
if [[ "$path" == *"@"* ]]; then
  # 包含基准分支
  path_part="${path%%@*}"
  base_branch="${path##*@}"
else
  # 无基准分支，使用默认 master
  path_part="$path"
  base_branch="master"
fi

# 判断是目录还是文件
if [ -d "$path_part" ]; then
  # 目录：获取该路径下与基准分支的差异文件
  git diff --name-only "origin/$base_branch" -- "$path_part" | grep -E '\.(js|ts|jsx|tsx|vue|css|scss|less|html)$'
elif [ -f "$path_part" ]; then
  # 文件：检查该文件是否与基准分支有差异
  if git diff --name-only "origin/$base_branch" -- "$path_part" | grep -q .; then
    echo "$path_part"
  fi
fi
```

**用户未指定任何参数时的处理方式**：

- 直接检查当前还未提交的变更代码（工作区变更 + 暂存区变更）
- 不执行合并操作

```bash
# 获取所有未提交的变更文件（包括已暂存和未暂存）
git diff --name-only --cached          # 已暂存（staged）的变更
git diff --name-only                   # 未暂存（unstaged）的变更
git diff --name-only HEAD              # 与 HEAD 的差异（包括以上两者）
```

### 4.2 逐个分支审查

对于每个目标分支（或当前分支），执行以下操作：

#### 4.2.1 合并远程分支（仅当用户指定分支时执行）

```bash
git fetch origin
git merge origin/<分支名> --no-commit --no-ff
```

如果合并有冲突，记录冲突文件，继续处理下一个分支（不解决冲突）。

#### 4.2.2 代码审查

**用户指定分支时**：合并后进行审查（已合并的增量代码）
**用户指定路径时**：直接审查该路径下相对于基准分支的增量代码
**用户未指定任何参数时**：直接审查当前还未提交的变更代码

合并后进行全面的代码审查。**必须对所有变更文件逐一检查，严禁抽检或选择性检查。** 审查时使用相对路径标识文件。

**重要：每个问题必须给出解决方案/建议**，解决方案应包括：

- 具体修改建议
- 正确的代码示例
- 参考的规范文档

获取变更文件的相对路径（用户未指定参数时）：

```bash
# 获取所有未提交的变更文件
git diff --name-only --cached          # 已暂存（staged）的变更
git diff --name-only                   # 未暂存（unstaged）的变更
```

获取变更文件的相对路径（用户指定分支时）：

```bash
git diff --name-only --cached
git diff --name-only
```

获取增量文件（用户指定路径时）：

```bash
# 与基准分支比较获取增量
git diff --name-only "origin/master" -- "src/utils"
```

### 审查问题分类及解决方案模板

**规范问题**

- 命名规范：提供正确的命名示例
- 代码格式：提供格式化后的代码示例
- 注释规范：提供正确的注释示例
- 目录结构规范：提供正确的目录结构建议

**逻辑问题**

- 业务流程逻辑错误：分析业务流程，提供正确逻辑
- 条件判断逻辑问题：分析条件，提供正确的判断逻辑
- 边界条件处理：提供边界条件的处理方案

**性能问题**

- 循环中的重复计算：提供优化后的代码
- 不必要的DOM操作：提供减少DOM操作的方法
- 内存泄漏风险：提供避免内存泄漏的建议
- 大数据量处理：提供分页、虚拟列表等方案

**代码可优化点**

- 重复代码：提供提取公共方法的方案
- 可复用的组件：提供组件拆分建议
- 过长的函数：提供函数拆分方案

**Bug排查**

- 空值/空对象引用：提供空值检查方案
- 异步操作处理：提供正确的异步处理方案
- 异常捕获：提供异常处理建议
- 边界条件：提供边界条件处理方案

**无用代码**

- 未使用的变量/函数/import：提供删除建议
- 注释掉的代码：提供删除建议
- 死代码：提供删除建议

#### 4.2.3 撤销合并

代码审查完成后，撤销合并操作：

```bash
git merge --abort
```

或者如果已经commit了合并：

```bash
git reset --hard HEAD~1
```

## 注意事项

1. **必须全部检查**：无论变更文件数量多少，都必须逐一检查每一个变更文件，不能抽检、不能选择性检查、不能跳过任何文件
2. **逐文件审查**：对每个变更文件逐一读取和分析，确保不遗漏任何问题
3. **完整输出**：审查报告必须包含所有变更文件的问题，不能省略任何文件
4. **框架规范**：根据项目类型应用对应的框架规范检查，详细规范见同目录下的规范文件：
   - `common-rules.md` - 通用规范（所有项目必检）
   - `doc-rules.md` - 文档通用规约
   - `js-rules.md` - JavaScript 规范
   - `ts-rules.md` - TypeScript 规范（TS 项目必检）
   - `html-rules.md` - HTML 规范
   - `css-rules.md` - CSS 规范
   - `vue-rules.md` - Vue 规范（Vue 项目必检）
   - `react-rules.md` - React 规范（React 项目必检）
