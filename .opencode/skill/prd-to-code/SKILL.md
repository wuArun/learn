# PRD to Code - 产品需求与代码双向转换中心

本技能是产品需求文档(PRD)与代码双向转换的统一入口，根据用户的具体需求，智能路由到最适合的子技能进行处理。

## 四大核心功能

### 1. PRD分析转需求列表 (prd-to-wbs)

**功能说明**：
将PRD文档（Markdown、Word、PPT、Excel等格式）分析并转化为结构化的需求列表(WBS)，便于开发团队理解和执行任务分解。

**适用场景**：
- 产品经理提供了PRD文档，需要提取其中的需求点
- 需要对PRD进行结构化分析，生成WBS工作分解结构
- 新旧PRD对比，识别变更需求
- 生成需求文档供开发团队使用

**触发条件**：
当用户输入包含以下关键词时，使用此功能：
- "帮我分析一下这个PRD"
- "将这份文档转化为需求列表"
- "PRD分析"、"需求分解"
- "文档对比"、"生成需求文档"
- "提取需求"、"WBS"

**输出位置**：
所有生成的需求列表文档默认保存到 `/docs/wbs/` 目录下，文件名格式：`[模块名]-需求列表.md`

**工作流程**：
1. 读取用户提供的PRD文档（支持多种格式）
2. 扫描 `docs/prd/` 目录检查是否有历史PRD文档
3. 如无历史PRD但有代码，询问是否自动生成历史PRD
4. 分析PRD内容，提取结构化需求
5. 匹配需求到现有模块（或新建模块）
6. 生成需求列表文档到 `docs/wbs/` 目录

---

### 2. 代码转PRD (code-to-prd)

**功能说明**：
分析现有代码库，智能识别业务实体、流程、角色、权限等，生成符合企业级标准的产品需求文档(PRD)。

**适用场景**：
- 遗留项目没有PRD文档，需要从代码反向推导
- 新项目需要快速生成初始PRD文档
- 为代码库编写完整的需求文档
- 理解复杂系统的业务逻辑

**触发条件**：
当用户输入包含以下关键词时，使用此功能：
- "从代码生成PRD"
- "分析项目结构并创建需求文档"
- "将代码实现反向推导为产品需求"
- "为遗留项目编写文档"
- "理解代码功能并整理成规范文档"
- "生成PRD"、"写需求文档"

**输出位置**：
所有生成的PRD文档保存到 `docs/prd/` 目录下，包含：
- `00-产品概览.md` - 产品整体概述
- `[序号]-[流程名称].md` - 业务流程文档
- `[序号]-角色权限.md` - 角色定义和权限矩阵
- `[序号]-附录.md` - 接口清单、数据字典、错误码

**工作流程**：
1. 扫描项目结构，识别技术栈
2. 分析代码（实体层、接口层、业务层、数据层）
3. 提取业务信息（术语、角色、状态流转、业务规则）
4. 提取真实@TableName表名（禁止虚构）
5. 识别并标注Rosefinch技术组件
6. 生成完整的PRD文档集

### 3. 需求转代码 (add-to-future)

**功能说明**：
根据PRD文档或功能描述，自动分析需求、设计技术方案并生成可直接运行的代码。支持后端(Java)和前端(React)代码生成。

**适用场景**：
- 根据PRD需求实现具体功能
- 生成后端API接口
- 生成前端页面和组件
- 快速原型开发

**触发条件**：
当用户输入包含以下关键词时，使用此功能：
- "实现需求"
- "根据PRD进行实现"
- "生成代码"
- "添加功能"
- "add-to-future"
- "写代码"

**前置要求**：
使用此功能前，**必须先读取 `/docs/wbs/` 目录下的需求文档**。
- 只读取 `/docs/wbs/` 目录下的需求文档
- 禁止读取 `/docs/prd/` 或其他目录下的文档
- 识别并递归读取需求文档中引用的子文档（流程图、接口定义等）

**代码规范**：
- 入参出参禁止使用 `Map<String, Object>`，必须使用具体的DTO对象
- 使用 `@RequestBody` 接收复杂对象，禁止用 `@RequestParam` 接收多字段参数
- 使用项目中已注入的 `emailMessageSender` 发送邮件
- 遵循阿里JAVA开发规则
- 优先使用Rosefinch框架功能

**工作流程**：
1. 读取 `/docs/wbs/` 目录下的需求文档及其引用的子文档
2. 复述需求并澄清技术细节
3. 设计技术方案（技术栈、模块拆分、数据模型、API设计）
4. 等待用户确认方案
5. 生成代码（后端+前端）
6. 检查Rosefinch功能可用性
7. 执行API前后端一致性校验
8. 生成数据库DDL（如涉及数据库变更）
9. 最终确认

---

### 4. 刷新PRD (refresh-prd)

**功能说明**：
基于现有代码库的变更（Git Diff或Git Log），及时更新产品需求文档(PRD)，确保文档的时效性和准确性。

**适用场景**：
- 代码发生变更后，需要同步更新PRD文档
- 维护PRD文档与代码实现的一致性
- 更新流程、接口、权限等信息
- 定期同步文档

**触发条件**：
当用户输入包含以下关键词时，使用此功能：
- "刷新PRD"
- "更新产品需求文档"
- "同步代码变更到PRD"
- "维护PRD时效性"
- "代码变更后更新文档"

**变更识别方式**：
1. **Git Diff方式**：通过比较代码差异识别变更（默认）
2. **Git Log方式**：通过指定提交记录识别变更（支持commit hash或数量）

**输出位置**：
所有PRD文档存储在 `docs/prd/` 目录下，更新时：
- 保持原有文档结构
- 添加版本号和更新说明
- 记录变更来源和变更原因

**工作流程**：
1. 识别代码变更（Git Diff或Git Log）
2. 分析变更影响范围（模块、功能、接口、数据模型）
3. 更新受影响的PRD文档
4. 更新版本号和修订历史
5. 执行质量检查清单
6. 验证文档与代码一致性

## 重要约束（所有子技能通用）

1. **表名真实性**：必须提取真实的 `@TableName` 表名，禁止推断/虚构
2. **Rosefinch组件识别**：必须识别并重点标注Rosefinch技术组件
3. **禁止虚构**：禁止虚构Rosefinch服务类或注解，必须基于实际代码
4. **代码规范**：生成的代码必须符合阿里JAVA开发规范
5. **文档一致性**：确保PRD文档与代码实现保持一致
